# ძრავის არჩევა: Godot 4 vs Unity

**არჩევანი: Godot 4 (GL Compatibility renderer).**

| კრიტერიუმი | Godot 4 | Unity |
|---|---|---|
| 2D მობილური თამაში | მშობლიური 2D ძრავა, პიქსელის ზუსტი კოორდინატები, მსუბუქი | 2D მუშაობს, მაგრამ 3D ძრავის ზემოდან; უფრო მძიმე რანტაიმი |
| APK ზომა | პატარა (რამდენიმე MB ბაზა) | უფრო დიდი ბაზა |
| 2D ფიზიკა, განათება, ნაწილაკები | ჩაშენებულია (`CharacterBody2D`, `PointLight2D`, `CPUParticles2D`) | ჩაშენებულია (URP 2D Lights საჭიროა) |
| Android ექსპორტი | ჩაშენებული APK/AAB | ჩაშენებული |
| iOS ექსპორტი | Xcode პროექტის გენერაცია (macOS საჭიროა) | იგივე, macOS საჭიროა |
| ლიცენზია | MIT, საკომისიო/რეგისტრაციის გარეშე | პირობები ფასების პოლიტიკაზეა დამოკიდებული |
| ტექსტური პროექტი (Git, ავტომატური გენერაცია) | `.gd` / `.tscn` ტექსტია — კოდიდან პირდაპირ იწერება | ძირითადად ბინარული/Editor-ზე დამოკიდებული |

**დასკვნა:** ყველა მოთხოვნილი მექანიკა (2D ფიზიკა, ანიმაცია, განათება, ნაწილაკები, მულტი-შეხება) Godot 4-ში გვაქვს ჩაშენებული. Unity-ს უპირატესობა (დიდი ასეტ-მარკეტი, რეკლამის/ანალიტიკის SDK-ები, 3D) ამ პროექტისთვის გადამწყვეტი არ არის.

**რატომ GL Compatibility და არა Mobile (Vulkan):** 2D თამაშისთვის OpenGL ES 3 ყველაზე ფართო თავსებადობას და ნაკლებ ბატარეის/სითბოს დატვირთვას იძლევა, განსაკუთრებით სუსტ Android მოწყობილობებზე. თუ მომავალში 3D ეფექტები დაგჭირდება, შეიძლება გადასვლა.

**რისკი Godot-ში:** მესამე მხარის მონეტიზაციის/ანალიტიკის SDK-ებისთვის ხშირად საჭიროა ცალკე Android/iOS პლაგინი.
